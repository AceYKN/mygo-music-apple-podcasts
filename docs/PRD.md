# 产品需求：Apple Podcasts 接入 MyGo Music

版本：0.1 需求基线 · 日期：2026-11-10

需求范围已按使用者意见确定；技术方案和验收阈值为实施基线。已有开发预览，实际完成范围见[验证记录](VALIDATION.md)；本文列出正式首版的完整要求，不代表全部通过验收。

## 1. 产品目标

在 MyGo Music 中使用已登录的 Apple Podcasts 账号。资料库和收听状态与苹果端保持一致，在 MyGo 上的改动也能回到苹果端。账号已有权限的免费、付费单集，都应采用同样的播放操作。

“完整同步”以本文列出的数据和行为为准，不能用“列表能显示”“登录成功”或“能播放免费节目”替代。

## 2. 使用场景

1. 在手机苹果播客中关注一档节目，回到电脑的 MyGo 后能看到它，并打开全部可用单集。
2. 在 MyGo 中关注、取消关注、保存或取消保存单集，手机或苹果网页刷新后看到相同状态。
3. 在手机上听到某个位置，在 MyGo 继续；在 MyGo 暂停后，再从手机继续。
4. 在任一端标记已播放或未播放，另一端显示一致，不能把标记未播放误判为旧数据。
5. 已经在苹果端付费订阅节目，在 MyGo 中点开会员单集即可收听，无需再付一次费。
6. 关闭并重开 MyGo 后，账号、资料库和最新可确认的播放位置仍可恢复。

## 3. 首版范围

下表均为正式首版必需项。开发可以分阶段，但未通过这些项目时只能称为预览版，不得称为“完整同步版”。

| 编号 | 需求 | 完成条件 |
| --- | --- | --- |
| R01 | 苹果官方网页登录、退出和恢复会话 | 登录有效性由账号接口确认；关闭并重开程序后可恢复；失效后可以重新登录 |
| R02 | 读取账号实际资料库 | 完整分页获取关注节目、已存单集、频道或订阅权益相关列表；空列表与获取失败分别处理 |
| R03 | 关注节目双向同步 | MyGo 的关注/取消关注写回苹果，苹果端变化能刷新到 MyGo |
| R04 | 已存单集双向同步 | 保存/取消保存均写回苹果，界面只在确认结果后显示成功 |
| R05 | 已播放状态双向同步 | 能读取并修改已播放/未播放，重启、刷新后仍一致 |
| R06 | 精确播放位置与断点续播 | 读取苹果端最新位置；MyGo 播放、暂停、拖动、切集后的有效位置能回到苹果端 |
| R07 | 继续播放与收听记录 | 展示账号真实数据，续播使用对应单集和位置；本机记录不能冒充苹果记录 |
| R08 | 节目、单集搜索与浏览 | 搜索节目和单集，支持苹果分享链接；展示简介、封面、日期、时长和节目归属 |
| R09 | 免费单集完整播放 | 正常控制播放、暂停、定位、音量、切集和队列；不能把试听片段当完整音频 |
| R10 | 已有权益的付费单集完整播放 | 在账号授权范围内完整播放，并支持暂停、定位和断点续播；需要真实权益账号验收 |
| R11 | 账号、地区和权益变化 | 跟随账号实际 storefront；切换账号后不混用资料库、队列状态和缓存；权益过期时提示具体原因 |
| R12 | 可观察、可恢复的同步 | 刷新、同步中、待重试、会话失效、冲突和失败有明确状态；不能静默丢弃操作 |

## 4. 交互约定

### 4.1 登录与首次使用

在 MyGo 的来源中选择 Apple Podcasts，点击登录后打开苹果官方页面，由使用者完成账号和验证码操作。登录成功后自动载入资料库，并显示当前账号和同步状态。

推荐技术路线需要本机 Chrome 和插件辅助程序。首次使用时一次说明依赖、下载体积及启动程序权限；每次播放不再展示技术细节。登录窗口必须可见，普通收听不要求反复切到浏览器。

### 4.2 导航

- 首页：继续播放、最新更新、关注节目。
- 关注节目：账号节目列表与完整节目页。
- 已存单集：对应 Apple Podcasts 的“已存储/已存”语义，不另建一套本地喜欢列表。
- 收听记录：平台实际提供的历史与已播放状态；如平台只提供部分记录，明确范围。
- 搜索：节目、单集、苹果链接。

### 4.3 播放与权限

免费和已授权付费单集使用相同的播放入口。未授权、地区不可用、已下架、网络失败应分别提示。付费节目保持可见，并准确显示账号是否有播放权限。

购买、续费和取消付费订阅跳转苹果官方页面办理；本插件同步已有权益，不处理付款。

### 4.4 同步状态

点击关注或保存后，可先显示“正在同步”，待服务端读回确认后显示成功。结果未知时先重新读取状态，不能盲目重复提交。

进入来源、切回前台、用户手动刷新和完成写入后触发拉取。界面保留最后成功的结果，并标明是否过期，避免网络失败把资料库清成空。

### 4.5 续播与冲突

默认使用苹果端最新可确认位置，不自动从头播放。使用者主动拖回前面、从头播放或标记未播放都是有效操作，不能用“取最大进度”覆盖。

另一设备正在播放、离线期间出现两端改动或无法比较记录时间时，需要遵循苹果端实际冲突行为，并在必要时让使用者选择从云端还是本机位置继续。

## 5. 验收标准

以下时间和误差是待原型确认的产品目标，不是已经测得的性能。

| 编号 | 场景与预期 |
| --- | --- |
| A01 | 真实账号完成官方登录；重启 MyGo 与辅助程序后无需重新输入密码即可恢复有效会话 |
| A02 | 将 MyGo 资料库与苹果端逐项对照，分页、去重、关注和已存状态一致 |
| A03 | 两端分别新增和删除关注/保存单集，互相刷新后结果一致；断网失败不会显示虚假的成功 |
| A04 | 手机播放到位置 T 后暂停，MyGo 从苹果端最新已确认位置续播，误差目标不超过 3 秒 |
| A05 | MyGo 播放、暂停、拖动、切集、播放结束、正常退出后，苹果端可读回正确位置或完成状态 |
| A06 | 主动倒退、从头听、标记未播放、多设备交替播放，不会被旧快照反复覆盖 |
| A07 | 服务端已能读到另一端变化后，MyGo 下一次前台刷新目标在 15 秒内反映；另行记录苹果端传播延迟 |
| A08 | 真实会员专属单集播放超过其公开试听长度，并验证中段/接近结尾的定位；不能仅凭开头能出声判定通过 |
| A09 | 账号退出或权益失效后，界面准确反映状态；第二个账号看不到前一个账号的私人数据 |
| A10 | 隐藏或最小化播放窗口后继续收听；辅助程序、Chrome 或网络中断后，MyGo 能提示并恢复控制 |
| A11 | 单集少于一页、跨多页、空资料库、单集下架、音频多次跳转和超时均有可解释结果 |
| A12 | 锁定 Windows x64 安装包，在干净环境中按说明安装并完成上述验收；其他平台另行标注状态 |

每项都要记录环境、复现动作、实际结果和证据；未测就是未测。付费播放需要使用者已有权益的测试样本，缺少样本时保留该需求并标为未验收，不能删除需求或假称通过。

## 6. 边界

首版重点是账号资料库、收听状态和播放体验。评论、评分、章节、逐字转录、OPML、批量离线下载及视频播客单独列后续需求，不以它们替代首版同步目标。苹果账号的支付管理与 iOS 系统设置不属于插件同步对象。

## 7. 发布条件

正式首版要求 R01–R12 对应验收通过。账号同步、进度同步和付费播放中的任一关键能力未通过，只能发布明确列出缺口的预览版。文档、仓库说明和插件内提示须保持一致。

需求来源：使用者已明确要求完整读取、全部同步、跨设备播放进度，以及账号已有权限的会员专属单集播放。
